## 0. 使用说明（纪律）

1. **一轮一记录**：每次「构建流水线运行」或「一次成体系的实机/本机验证」占**一个轮次**，编号从 `0` 递增，**只增不改**。
   追加式写入：新轮次追加在 §2 之后（或按轮次顺序追加），**不覆盖**历史轮次；发现旧结论有误时**新开一轮**并注明「修正轮次 N 的结论」。
2. **环境字段必须逐项填**（不允许「同上」）：OS 与版本、Node 版本、Electron 版本、`pi` 与 `pi-web` 的**版本 + commit SHA**（来自 `upstream.lock.json` 或 `git -C ../pi rev-parse HEAD`）。
3. **命令必须写原文**：直接粘贴实际执行的命令（含参数、环境变量前缀），不要写「跑了一遍流水线」。
4. **结果必须是三项计数**：`PASS / FAIL / SKIP`（例如 `9 PASS / 1 SKIP / 0 FAIL`）。只有一个笼统的「成功/失败」视为无效记录。
   - 有断言脚本时，计数以脚本输出为准；
   - 无断言脚本时，把人工步骤逐条编号，每条只能记 `PASS / FAIL / SKIP`。
5. **证据必须落盘且可复现**：日志片段、脚本 stdout、HTTP 响应头/体、截图、产物 `ls -l` 输出。
   证据路径写**相对本工程的路径**，统一放 `logs/<YYYYMMDD>-<轮次>/`（`logs/` 已 gitignore，不入库）或 `docs/evidence/`（截图等需要入库的小体量证据）。
   **不接受**「见某次终端输出」这类没有落盘的证据。
6. **FAIL 必须追根因**：附原始输出的关键行 + 判定（代码缺陷 / 环境问题 / 上游行为变化 / 平台约束）+ 下一步动作与责任人。
   **SKIP 必须写原因**（缺哪个前置条件、需要哪个更好的环境）。
7. **结论回写规则**：任何影响能力判定的结论，必须同步回写 `docs/桌面能力清单.md`（把那一条 ⬜/⚠️ 改成 ✅ 并附本文件轮次号 + 证据路径）。
   **只在本文件写结论而不回写能力清单，视为未完成。**
8. **沿用不得当实测**：`dsh-desktop` / `pi-desktop-hos` 的既有结论写在本文件时，必须标注 `🔶 沿用（来源：…）`，**不得**写成「本工程实测」。
9. **无实测值的项不许填估算值**：安装包体积、首启耗时、内存占用等一律先写 `⬜ 未测量`，测到之后再写「实测值 + 测量方法（命令/工具）+ 样本数」。
10. **凭证与隐私**：证据里不得出现 `PI_WEB_PASSWORD` 明文、`auth.json` 内容、API Key、用户会话内容；
    日志片段里这些字段要打码（密码只保留长度）。

**关键发现**

1. **打包态就绪失败的根因是「跨盘符」而不是「反斜杠」**（更正方案文档原结论）：Next 用 `join(process.cwd(), path.relative(process.cwd(), dir))` 还原项目根（`next/dist/server/route-modules/route-module.js` → `load-manifest.external.js`），Windows 的 `path.relative()` 跨盘符只能返回绝对路径 → 拼出 `<cwd>\C:\…\pi-dist\C:\…\pi-dist\.next\routes-manifest.json` → 每个请求 500 → 就绪超时。对照探针（同一产物、同一 Node）：不 chdir 复现 ENOENT（`evidence/TC13-probe-A-*.log`）、chdir 后第 1 次探测 200（`evidence/TC13-probe-B-*.log`）。**处置**：`host.ts` 起服务前 `process.chdir(<产物根>)` + 跨盘符 fail-visible 守卫（本轮已改、已重建、已复验）。
2. **终端 / PTY 在打包态不可用**（域外：属 002/010 的能力问题，非品牌化回归）：`POST /api/terminal` → 500 `Cannot find module './prebuilds/win32-x64/conpty.node'`；上游安装态 `../pi-web/node_modules/node-pty/prebuilds/win32-x64/` 只有空的 `conpty/` 目录、无任何 `.node`（`build/Release/` 亦只有 `conpty.dll` + `OpenConsole.exe`）。`collect-pi` 的 prebuilds 裁剪只删非目标平台目录，**未丢文件**。
3. **品牌替换的绝对计数是构建相关的**：本轮 `Pi Web` 1035 处 / 36 文件（标识符 757）；`pi-desktop-hos` 同型产物是 1055 处 / 750。机器判据 = 「替换后 0 处」+「标识符逐项不变」+「`/icons/logo.svg` = 6 处」。
4. **打包态看不到登录页**（符合设计）：`GET /login` 被代理重定向回 `/`（会话 cookie 注入生效）；登录页品牌化只能由构建期对 `.next/server/app/login.html` 的断言覆盖（`Pi Web`=0、`Pi Desktop`=9、`/icons/logo.svg`=2）。
5. **提示**：AI 代理环境里「启动 GUI 子进程」必须让它活过命令边界，否则会被连带的 Job 收尾杀掉（本轮首次启动即被 Silent kill，表现为「主窗口已显示」后日志戛然而止、无任何崩溃记录）。

**评审修复后复验（同一轮次，追加；代码变更与逐条处置见 `logs/20261013-0/REVIEW_REPORT.md`）**

评审（`requesting-code-review` 派发独立评审 → `receiving-code-review` 逐条核实后处置）共 6 条 Minor 发现，**4 条有效并修复**：
① `host.ts` 的守卫原本放在 `chdir` **之后**（此时 `path.relative(cwd, dir)` 恒为 `''`，断言永不成立＝死代码）→ 改为「用 `samePath()` 决策是否 chdir + 只校验 chdir 生效」（大小写 / 正反斜杠差异不算不同）；
