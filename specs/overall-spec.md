# overall-spec.md — 整体规格

> pi-desktop 系统级功能规格（**技术无关**，2026-10-12）。
> 本文档描述系统「做什么、为什么」，不涉及实现细节；实现方案见 [overall-plan.md](./overall-plan.md)。
> 需求条目来源：[`../docs/工程规划.md`](../docs/工程规划.md) §3 目标、§4 架构决策、§5 桌面壳能力、§9 范围。
> 编号规则：项目级统一使用 `FR-000-<三位数>`（`specs/README.md` §四）。动作用 **MUST / MUST NOT / SHOULD / MAY** 表述。

---

## 1. 系统目的与目标用户

**目的**：把 [Pi](https://pi.dev)（可扩展的 agent harness）与其浏览器界面 Pi Web 封装成
**Windows / macOS / Linux 的一等公民桌面应用** —— 用官方 Electron 43 承载 `pi-web` 的 Next 服务器（含 agent 与 `/api`），
渲染层同源加载该服务端提供的 Pi Web UI；桌面壳补齐 Pi 自己没有的东西，最终产出三平台可分发安装包。
**不是**「包一层浏览器指向 localhost」的粗壳（工程规划 §1.1、§3 目标 1）。

**目标用户**：

1. **已在用 `pi` CLI 的开发者**：希望桌面应用**直接复用**现有的 `~/.pi/agent`（凭据、会话、扩展、MCP、技能），
   开箱即用而不必重新配置（Q6 默认共享数据目录）。
2. **希望有原生桌面体验的用户**：托盘、原生通知（后台提醒）、单实例、窗口状态记忆、外链走系统浏览器、更新引导。
3. **需要完整 UI 能力的用户**：会话管理、流式对话、工具调用可视化、审批交互、文件读写、终端、模型与凭据配置
   —— 全部由上游 UI 提供，本工程**不重写**。

**上游身份声明**：本工程名称含 `pi`；`Pi` 与 `Pi Web` 分别是上游开源项目（MIT，`earendil-works/pi`；MIT，`agegr/pi-web`）。
本工程是二者在**桌面平台**上的第三方封装，与上游作者无隶属关系、未获其背书；README 与应用内「关于」必须据此注明，
并声明「不 fork、只装配」（工程规划 §1.4）。

## 2. 核心能力（用户故事）

- 作为用户，我希望双击应用后**直接进入我已配置好的 Pi 环境**（凭据、会话、扩展都在），看到完整的 Pi Web UI。
- 作为用户，我希望**长任务在后台跑完时收到原生通知**，而不必盯着窗口；把窗口切到前台时不要再被通知打扰。
- 作为用户，我希望**关掉窗口就等于退出应用**，不留后台进程、不留孤儿服务端口。
- 作为用户，我希望**再次双击应用时唤回已有窗口**，而不是开出第二个实例、第二个服务器。
- 作为用户，我希望**窗口尺寸/位置被记住**，下次打开还在我放的地方。
- 作为用户，我希望**点击对话里的外链时用系统浏览器打开**，应用窗口始终保持是 Pi Desktop 自己。
- 作为用户，我希望**能切换数据目录**（共享 `~/.pi/agent` ↔ 应用私有），以便隔离或做多环境实验。
- 作为用户，我希望**能检查更新**：有新版本时告知我版本号并打开下载页，而不是静默安装。
- 作为构建者，我希望**一条命令链从零产出三平台安装包**，并有门禁保证产物不是「能打包但跑不起来」。

## 3. 功能需求（按域编号）

### 3.1 应用生命周期（FR-000-001 … 009）

- **FR-000-001**：系统 **MUST** 保证应用单实例运行；重复启动时唤回（`restore → show → focus`）已有主窗口，且**不启动第二个服务端**（工程规划 §5.1）。
- **FR-000-002**：系统 **MUST** 在主窗口创建前完成「环境装配 → 产物就位 → 服务端就绪」的前置链，避免渲染层加载竞争（§4.7）。
- **FR-000-003**：系统 **MUST** 在关闭主窗口时退出整个进程并释放服务端（关窗即退出）；若存在运行中的 agent 会话，**SHOULD** 在关闭前给出一次确认提示（§5.2）。
- **FR-000-004**：系统 **MUST** 支持从托盘菜单退出，且该入口与关窗走**同一条**优雅关闭链（§5.3）。
- **FR-000-005**：系统 **MUST** 在退出时按「置退出标志 → 关闭 SSE → 关闭 HTTP 服务器 → 超时强制退出」的时序执行，
  强退上限 **MUST NOT** 超过 `PI_WEB_SHUTDOWN_DEADLINE_MS`（默认 5000 ms）（§4.2 ⚠️、§11.1 R8）。
- **FR-000-006**：系统 **MUST** 在每个启动阶段可观测（阶段名 + 耗时 + 失败原因），**MUST NOT** 出现「卡住但不说」或静默降级（§4.7，fail-visible）。
- **FR-000-007**：系统 **MUST NOT** 留下孤儿进程或占用端口的残留服务端（Q2 选定进程内宿主的直接收益）。
- **FR-000-008**：系统 **MUST** 在 macOS 上于 `activate` 且无窗口时重建主窗口（平台惯例，§5.2）。
- **FR-000-009**：系统 **MUST** 将崩溃（`uncaughtException` / `unhandledRejection`）与渲染失败（`did-fail-load` / `render-process-gone`）
  记录到应用日志，**MUST NOT** 静默崩溃（§4.3、§5.2）。

### 3.2 宿主与服务端（FR-000-010 … 019）

- **FR-000-010**：系统 **MUST** 在 Electron **主进程内**启动 `pi-web` 的 Next 服务器（含 agent），**MUST NOT** 依赖 `pi` 二进制存在于 `PATH`（Q2、§4.2；✅ `pi-web/lib/rpc-manager.ts` 进程内 import SDK）。
- **FR-000-011**：服务器 **MUST** 绑定 `127.0.0.1` 与**随机高位端口**；**MUST NOT** 绑定 `0.0.0.0`、**MUST NOT** 使用固定默认端口 30141 作为生产绑定（§4.5、§11.4 S3）。
- **FR-000-012**：系统 **MUST** 在起服务前注入 `PI_WEB_PASSWORD`（随机强密码）与 `PI_WEB_HOSTNAME=127.0.0.1`；
  密码 **MUST NOT** 出现在日志或界面上（§4.5、§11.4 S2）。
- **FR-000-013**：系统 **MUST** 在起服务前完成预览密钥轮换（复用上游脚本重写 `.next/prerender-manifest.json`），
  否则 `x-prerender-revalidate` 可绕过上游 `proxy.ts` 的认证门禁（§2.2、§4.2）。
- **FR-000-014**：系统 **MUST** 同时注入**两件**凭据：出栈到本服务 host:port 的 `Authorization: Basic pi:<password>`（覆盖 `/api/*` 与 SSE）
  **与** 页面导航所需的 `pi_web_session` cookie；**MUST NOT** 只注入其中一件（§4.5）。
- **FR-000-015**：就绪判定 **MUST** 采用 HTTP 轮询（探活端点可选免认证的 `/api/web-auth`），**MUST NOT** 解析子进程 stdout 的 `Ready`（§4.2）。
- **FR-000-016**：就绪判定 **MUST** 有超时上限（默认 30 s），超时 **MUST** 作为可见失败上报（§4.7）。
- **FR-000-017**：渲染层 **MUST** 同源加载 `http://127.0.0.1:<port>/`；系统 **MUST NOT** 引入自定义协议、**MUST NOT** 改写上游请求基址（§4.3）。
- **FR-000-018**：系统 **MUST NOT** 写入上游 CLI 的 run-record 文件（那是 `bin/pi-web.js` 启动器的行为，§4.2）。
- **FR-000-019**：系统 **MUST** 支持开发期绕过内嵌服务器（`PI_DESKTOP_DEV_SERVER` / `PI_DESKTOP_PI_DIST` 一类开关），
  以避免「改一行 UI 代码就要打包」的调试往返（§8.4）。

### 3.3 桌面壳能力（FR-000-020 … 029）

- **FR-000-020**：系统 **MUST** 提供系统托盘（单例）与菜单：显示主窗口 / 会话目录 / 打开日志 / 检查更新 / 退出；
  托盘 **MUST** 在宿主未就绪时也可创建，菜单项按就绪态**禁用**而不是消失（§5.3）。
- **FR-000-021**：系统 **MUST** 在 agent 完成一轮任务时发出原生通知，**MAY** 在出错时发出「出错了，请查看应用详情」（§5.4）。
- **FR-000-022**：通知策略 **MUST** 满足：仅当主窗口**不可见或未聚焦**时弹出；同一会话在冷却窗口（默认 10 s）内去重；
  应用启动前的历史消息 **MUST NOT** 补弹（§5.4）。
- **FR-000-023**：系统 **MUST** 持久化主窗口状态（尺寸 / 位置 / 最大化），并对多显示器可见性做校验，异常状态回退默认（§5.2）。
- **FR-000-024**：系统 **MUST** 提供 `F11` 全屏切换，并在 `ready-to-show` 后再显示窗口（避免白屏闪烁）（§5.2）。
- **FR-000-025**：主窗口 **MUST** 使用常规系统标题栏（原生最小化/最大化/关闭），**MUST NOT** 实现无边框自绘标题栏与窗口控制 IPC（§5.2、§5.8）。
- **FR-000-026**：系统 **MUST** 拦截 `window.open`、**MUST** 将 http/https 外链交给系统浏览器打开（§4.3、§5.5）。
- **FR-000-027**：系统 **MUST** 提供「检查更新」入口（应用菜单 / 托盘 / 关于）：查询更新源 → 语义化版本比较 →
  有新版则展示版本号并打开下载页；**MUST NOT** 自动下载或静默安装（Q5、§5.7）。
- **FR-000-028**：检查更新失败（网络不可达等）**MUST** 提示「无法检查更新」并留痕，**MUST NOT** 阻塞或误报（§5.7）。
- **FR-000-029**：系统 **MUST** 提供「关于」信息（产品名、应用版本、Electron/Node/Chromium 版本、上游基线）（§5.7、§8.4）。

### 3.4 安全（FR-000-030 … 039）

- **FR-000-030**：渲染进程 **MUST** 以 `sandbox: true` + `contextIsolation: true` + **无 `nodeIntegration`** 运行（§4.5）。
- **FR-000-031**：系统 **MUST** 通过 Fuses 关闭危险能力：`RunAsNode`、`NODE_OPTIONS`/`NODE_CLI_INSPECT` 环境与参数入口；
  **MUST** 开启 asar 完整性校验并只从 asar 加载应用代码（§4.5、§11.4 S5）。
- **FR-000-032**：系统 **MUST** 做导航加固：新窗口一律拒绝、原地导航仅允许应用自身来源与明确白名单外链（§4.5、§11.4 S6）。
- **FR-000-033**：系统 **MUST** 用**权限白名单**处理权限申请（仅 `notifications`，必要时 `clipboard-sanitized-write`），
  并校验来源 URL 与对应 `webContents.id`；其余权限 **MUST NOT** 授予（§4.5）。
- **FR-000-034**：数据面 **MUST NOT** 经过 IPC：业务数据只走同源 HTTP + SSE（§4.8、[constitution.md](./constitution.md) §3.1）。
- **FR-000-035**：preload **MUST** 只承载壳层动作，且**只对壳层自有文档（`file://` 的 loading/降级页）暴露**；
  **MUST NOT** 向 Pi Web UI 页面暴露任何壳能力或 Node 能力（§5.6、Q 说明见 constitution §3.3）。
- **FR-000-036**：loopback 地址 **MUST** 并入 `NO_PROXY`/`no_proxy`，并设置 Chromium 的 `proxy-bypass-list <-loopback>`，
  避免企业代理拦截本地服务（§4.5）。
- **FR-000-037**：系统 **SHOULD** 合并系统 CA（`getCACertificates('system')` → `setDefaultCACertificates`），
  且在能力缺失时**安全降级不抛错**（§4.5）。
- **FR-000-038**：生产构建 **MUST NOT** 携带 `--inspect` 或 `remote-debugging-port`；DevTools 与 `openDevTools()` **MUST** 仅 dev 开启（§8.4、§11.4 S1/S4）。
- **FR-000-039**：本地服务 **MUST NOT** 启用 mDNS/局域网发现，**MUST NOT** 写入 run-record（减少暴露面）（§4.5）。

### 3.5 构建与发布（FR-000-040 … 049）

- **FR-000-040**：上游基线 **MUST** 固定在 tag（`pi` v1.1.0 / `pi-web` v0.11.1），**MUST NOT** 依赖浮动分支（§6.1、§11.1 R10）。
- **FR-000-041**：构建 **MUST** 从上游源码产出 `pi-dist`（`pi-web` 的 `.next` + 运行依赖），
  并按目标平台裁剪原生件（**MUST** 在副本上裁剪，不删源目录）（§8.1、§8.2）。
- **FR-000-042**：分发产物 **MUST** 为 `pi-dist.tar.gz`（ustar 格式）+ 首启解压到 `<userData>/pi-dist`，
  幂等判据 **MUST** 是内容 SHA-256（marker）而**不是**「目录是否存在」（Q3、§8.3）。
- **FR-000-043**：安装包 **MUST** 通过 `extraResource` 携带 `pi-dist.tar.gz` 与图标资源；`asar` **MUST** 开启，
  可执行名 **MUST** 为 `pi-desktop`（Linux maker 依赖 `package.json.name`，§8.5 注意 5）。
- **FR-000-044**：`npm run make` **MUST** 为一条可复现命令（`prepackage`/`premake` 自动串联产物准备）（§8.1 ④）。
- **FR-000-045**：流水线 **MUST** 在打包前通过门禁：`npm run typecheck` **与** 冒烟脚本（SPA / 带凭据 `/api/*` / SSE 可建连 / SDK 可建会话）
  全部通过；门禁失败 **MUST** 阻断打包（§8.1 ②、§8.4）。
- **FR-000-046**：CI **MUST** 使用与运行时同版本的 Node（**24.21.0**），并覆盖 `windows-latest` / `ubuntu-latest` / `macos-latest` 矩阵（§8.5）。
- **FR-000-047**：构建 **MUST** 记录上游 commit SHA（`upstream.lock.json`）以保证可复现（§6.1）。
- **FR-000-048**：发布 **MUST** 通过 GitHub Release 上传三平台安装/压缩包资产；v1 **MUST NOT** 要求签名或公证（Q5、§8.5）。
- **FR-000-049**：补丁集 **MUST NOT** 超出登记范围；本版为 0 条必需补丁，任何新增补丁 **MUST** 登记触发条件、实施时机与替代方案，并遵守幂等/冲突即终止规则（§7）。

## 4. 非功能需求

| 维度 | 要求 | 依据 |
|---|---|---|
| **性能** | 首启解压 + 起服务 + 首屏的耗时必须**实测并记录**（⬜ O4）；期间 loading 页必须显示阶段与耗时；交互延迟不得因内嵌宿主而不可接受 | §8.3、§11.1 R3/R5 |
| **可靠性** | 首启解压可断点重入（重新解压覆盖）；服务端失败必须可见并可重试；退出链必须有 deadline 强退 | §8.3、§4.7、§4.2 |
| **可移植性** | Windows（主验证）/ macOS / Linux 三平台；平台差异必须台账化并有统一降级策略 | Q1、§9.3 |
| **可维护性** | 宿主进程边界可迁移（进程内 → sidecar）而**不改变渲染层契约**；上游机制结论必须带文件路径 | §4.2、§12.1 硬规则 8 |
| **安全性** | 渲染层加载的是「本地服务提供的可执行能力界面」，**必须按不可信内容对待**；本地服务具备文件读写与命令执行能力，鉴权默认开启 | §4.5、§11.4 |
| **可用性** | 应用内文案与 Pi Web UI 语言一致（中文/多语言沿上游）；壳层文案为中文 | §9.1、§5 |
| **可观测性** | 统一日志前缀 `[pi-desktop]`、落盘 `<userData>/logs/`；loading 页可打开日志 | §4.7、§8.4 |
| **体积** | 安装包体积需实测后定基线；必须做按平台裁剪与无关文件剔除 | §11.1 R12 |
| **国际化** | 壳层自有页面（loading/失败页）**MAY** 仅提供中文（v1）；主界面国际化由上游提供 | §2.2、§9.1 |

## 5. 系统边界

### 5.1 在范围内（v1 必须达成）

三平台安装包可安装启动；内嵌服务端就绪、`GET /` 返回 SPA、带凭据的 `/api/*` 通过；
**Pi Web UI 全功能可用**（会话、流式对话、工具调用、审批、用量/成本、主题、多语言）；会话持久化；
模型与凭据配置（共享 `auth.json`）；工作目录选择；文件类工具；终端面板（受 `node-pty` ⬜ 制约）；
桌面壳能力（托盘、通知、单实例、窗口状态、外链、检查更新）；构建可复现（一条命令链 + 门禁 + 上游 SHA）
（工程规划 §9.1 的 10 条）。

### 5.2 不在范围内（二期及以后）

| 项 | 原因 | 计划 |
|---|---|---|
| 代码签名 / 公证 | 需证书与 Apple 账号；不影响功能闭环 | Phase 3（§11.3） |
| 深链 / 自定义协议 | 无明确需求；涉及跨平台注册细节 | Phase 2 评估 |
| 开机自启 / 全局快捷键 / 多窗口 | 参考工程同样暂缓 | Phase 2 评估 |
| 关窗最小化到托盘（常驻） | 需产品决策 + 会话运行态判定方案 | Phase 2（§11.2 O8） |
| macOS 模板托盘图标与平台视觉细节 | 需设计产出 | Phase 2 |

### 5.3 明确排除（本工程不做）

1. **fork 上游 UI**：`pi` / `pi-web` **MUST NOT** 被 fork 或改写；只允许幂等补丁（本版 0 条）（§0.4、§7）。
2. **新写 IPC 数据载体**：不引入任何传输业务数据的 IPC 通道（§4.8、§5.6）。
3. **自定义协议**（`app://` 等）：会触发上游 Host/Origin 校验失败，且需改写请求基址（§4.3）。
4. **独立插件市场工程**：上游 UI 已内置 Plugins/Skills/MCP 管理（Q7）。
5. **静默自动更新**：v1 只做「检查更新 → 打开下载页」（Q5）。
6. **代码签名与公证**：v1 产出的安装包未签名（Windows 直装、macOS 需右键打开、Linux 直装）（Q5、§11.3）。
7. **内置便携 Node/pnpm 运行时**：无市场安装链路需要（桌面本就有 npm/git）（§6.3）。
8. **主 UI 的离线化 / 静态导出**：`pi-web` **不可静态导出**（有 route handler / SSE / fs / PTY / middleware）（§4.3）。
9. **原生文件选择器**：沿用 Pi Web UI 内置目录浏览（§5.8）。
10. **AI 内容标识等平台合规项**：桌面分发无此合规要求（§5.8）。
