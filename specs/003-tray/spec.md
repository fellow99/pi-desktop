# 003 — 系统托盘（tray）功能规格

> **Module:** 003-tray（系统托盘）  **Status:** Proposed  **Last Updated:** 2026-10-12  **上游基线:** pi v1.1.0 / pi-web v0.11.1
> **对应方案:** [`./plan.md`](./plan.md)
> **实现落点:** `src/main/tray.ts`（资源 `resources/tray.png`、`resources/trayTemplate.png`）
> **规划依据:** `docs/工程规划.md` §5.3、§5.8、§9.3、§11.2 O7、§11.1 R4

## 1. 模块概述

### 1.1 目的

托盘模块的职责是：**用系统托盘提供应用的常驻入口 —— 唤回主窗口、直达会话目录与日志、触发检查更新、以及「真正退出」的唯一显式通道**，并显式处理三平台差异（macOS 模板图与单击行为）。

### 1.2 解决的问题

- **没有常驻入口**：主窗口最小化或落在其它窗口之下时，用户缺少一个稳定可见的唤回点。
- **排障入口太深**：问题发生时用户需要「一键打开日志」「一键打开会话目录」，而不是先找到 `<userData>` 路径。
- **退出语义歧义**：需要把「退出应用（走优雅关闭链）」与「关窗」「隐藏」区分开。
- **平台惯例**：macOS 托盘（状态栏）图标必须用模板图才能随深浅色主题自适应；Windows/Linux 单击托盘图标应唤回窗口，macOS 单击应弹出菜单（§5.3）。
- **宿主未就绪期的可用性**：启动期（含首启解压数十秒）托盘必须已经存在，否则用户既看不到进度也无处退出（§5.3：托盘在宿主未就绪时也创建）。

### 1.3 范围

**包含**

- 托盘单例的创建与销毁（含 `resources/tray.png`、macOS `trayTemplate.png`）。
- 右键/点击菜单：**显示主窗口**、**会话目录**、**打开日志**、**检查更新**、**退出**。
- 唤回主窗口的统一实现（最小化先还原 → `show()` → `focus()`）。
- 平台差异：macOS 模板图与单击弹菜单；Windows/Linux 单击唤回。
- 菜单项的就绪态/可用态管理（宿主未就绪时禁用而非隐藏）。

**不包含**

- 全局快捷键、开机自启、多窗口（§5.8 明确不做，Phase 2 评估）。
- 主窗口的创建与状态持久化 → 002-window。
- 「检查更新」的业务实现（版本比较、下载页跳转）→ 011-release-update；本模块只提供入口与展示。
- 优雅关闭链本身（`before-quit`、deadline 强退）→ 005-lifecycle / 007-app-entry。
- 原生通知 → 004-notification。

## 2. 用户故事

- 作为用户，我希望应用启动后（即使还在解压/启动中）就能在系统托盘看到图标，并能在菜单里读到当前状态。
- 作为用户，我希望单击托盘图标能立刻把主窗口唤到前台；被最小化时先还原。
- 作为用户，我希望从托盘菜单一键打开会话目录与日志目录，方便查看会话与排障。
- 作为用户，我希望托盘菜单里有「检查更新」，点一下就知道有没有新版本并能打开下载页。
- 作为用户，我希望托盘菜单的「退出」是真正的退出：进程必须结束，不留后台服务。
- 作为 macOS 用户，我希望状态栏图标在浅色/深色主题下都清晰（模板图），并符合「单击弹菜单」的平台惯例。
- 作为用户，我不希望菜单项在启动期「时有时无」——应当始终可见，只是在不可用时置灰。

## 3. 功能需求

动作词：**MUST** 必须满足；**MUST NOT** 禁止；**SHOULD** 建议；**MAY** 可选。

### 3.1 托盘创建与资源

- FR-003-001：系统 MUST 在应用启动时创建**单例**托盘（`Tray`），重复初始化 MUST 幂等（不产生第二个图标）。
- FR-003-002：系统 MUST 在宿主未就绪时也创建托盘；**MUST NOT** 因宿主未就绪而跳过托盘创建。
- FR-003-003：托盘 MUST 设置悬浮提示文本为产品名（`PRODUCT_NAME`）。
- FR-003-004：macOS 上托盘 MUST 使用模板图（`resources/trayTemplate.png`，`nativeImage.setTemplateImage(true)`）；Windows/Linux MUST 使用 `resources/tray.png`。
- FR-003-005：图标资源缺失或不支持托盘的环境下，系统 MUST 记录 WARN 并继续启动，**MUST NOT** 因此崩溃或阻塞启动流程。

### 3.2 菜单

- FR-003-006：托盘菜单 MUST 包含以下项（顺序固定，分隔线按需）：**显示主窗口**、**会话目录**、**打开日志**、**检查更新**、**退出**。
- FR-003-007：菜单项 MUST 按当前状态置灰或可点，**MUST NOT** 因状态变化而动态增删项（避免菜单结构跳动与用户肌肉记忆失效）。
- FR-003-008：**显示主窗口** MUST 调用 002 的唤回实现（`restore() → show() → focus()`）。
- FR-003-009：**会话目录** MUST 打开数据目录（`agentDir`）；目录不存在时该项 MUST 置灰（不得打开一个不存在的路径）。
- FR-003-010：**打开日志** MUST 打开日志落点（`<userData>/logs/` 或当日日志文件）；日志目录尚不存在时该项 MUST 置灰或由壳层按需创建后再打开。
- FR-003-011：**检查更新** MUST 委托 011-release-update 的实现；检查进行中该项 SHOULD 置灰并显示进行中文案。
- FR-003-012：菜单 MUST 在宿主就绪、窗口创建、检查更新状态变化后刷新（`setContextMenu` 重建），刷新 MUST 幂等。

### 3.3 唤回

- FR-003-013：用户单击托盘图标时：**Windows/Linux MUST 唤回主窗口**；**macOS MUST 弹出菜单**（平台惯例，不做唤回）。
- FR-003-014：唤回实现 MUST 处理「窗口最小化」「窗口被隐藏」「窗口已被销毁」三种状态：分别还原、显示、必要时由 007 重建。
- FR-003-015：唤回 MUST 使窗口获得焦点（`focus()`），且 MUST NOT 在窗口已聚焦时产生额外副作用。

### 3.4 退出

- FR-003-016：**退出** MUST 触发与「关窗退出」等价的退出流程（`before-quit` → 优雅关闭链 → deadline 强退），**MUST NOT** 直接调用 `app.exit()` 绕过关闭链。
- FR-003-017：退出流程中系统 MUST 销毁托盘资源（`tray.destroy()`），避免残留图标或悬挂引用。
- FR-003-018：**MUST NOT** 把「关窗」实现为「隐藏到托盘」——v1 关窗即退出（§5.2、§9.2）。

### 3.5 资源生命周期

- FR-003-019：应用退出时托盘资源 MUST 被释放；重复销毁 MUST NOT 抛错。
- FR-003-020：托盘 MUST NOT 持有窗口实例的强引用以外的长生命周期对象（避免应用退出后进程不结束）。

## 4. 关键实体

| 实体 | 说明 | 关键属性 |
|---|---|---|
| 托盘句柄（`Tray`） | 模块级单例 | 存在性（已创建/未创建）、图标来源、tooltip |
| 菜单项定义 | 五项固定结构 | `id`、`label`、`enabled`、`click` 动作、`separator` |
| 托盘状态（`TrayStatus`） | 决定各项 enabled 的输入 | `hostReady: boolean`、`agentDir: string \| null`、`logPath: string \| null`、`updateState: 'idle' \| 'checking' \| 'done'` |
| 图标资源 | 平台差异资源 | `resources/tray.png`（通用）、`resources/trayTemplate.png`（macOS 模板图）；二者均已产出（⬜ 仅 macOS 视觉待实机核） |

## 5. 验收场景

### 场景 S1：启动期托盘驻留

- Given 应用刚启动、宿主仍在解压/启动中
- When 托盘初始化完成
- Then 系统托盘中出现图标且 tooltip 为产品名；菜单显示五项，其中依赖宿主/目录的项置灰

### 场景 S2：单击唤回（Windows/Linux）

- Given 主窗口已最小化
- When 用户单击托盘图标
- Then 主窗口被还原、显示并聚焦

### 场景 S3：单击弹菜单（macOS）

- Given macOS 平台、应用在后台
- When 用户单击状态栏图标
- Then 弹出菜单（不直接唤回窗口），菜单项可用性与 Windows/Linux 一致

### 场景 S4：打开会话目录

- Given 数据目录 `<agentDir>` 存在
- When 用户选择「会话目录」
- Then 系统文件管理器打开该目录（`shell.openPath`）；若目录不存在，该项为置灰态

### 场景 S5：检查更新入口

- Given 已配置更新源且网络可用
- When 用户选择「检查更新」
- Then 显示检查中状态，随后给出「无更新」或「有新版本 + 打开下载页」的结果；网络失败时提示失败且不阻塞应用

### 场景 S6：托盘退出

- Given 应用在后台运行
- When 用户在托盘菜单选择「退出」
- Then 走优雅关闭链：宿主关闭、托盘销毁、进程退出；进程列表中无残留进程

### 场景 S7：无托盘环境不阻塞

- Given 运行在无托盘支持的 Linux 桌面环境（或图标资源缺失）
- When 应用启动
- Then 记录 WARN，应用继续启动到首屏；其它功能不受影响

## 6. 非功能需求

- **可靠性**：单例引用创建/销毁成对；菜单刷新幂等；唤回对边界状态（隐藏、已销毁）不抛错。
- **平台一致性**：五项菜单在三平台语义一致；差异只在图标形态与单击行为（§9.3 台账）。
- **性能**：托盘初始化与菜单重建为毫秒级；**MUST NOT** 为托盘引入轮询（状态变化由事件驱动刷新）。
- **可维护性**：菜单构造 SHOULD 抽成纯函数（`buildMenuTemplate(status)`），便于单测 enabled 组合。
- **安全**：托盘动作不暴露任何凭据、不打开任意用户输入路径（路径只能来自壳层自身枚举）。

## 7. 假设与约束

- **假设（🔶 沿用 dsh 范式）**：托盘在宿主就绪**之前**创建、菜单项按就绪态禁用而非消失 —— 这是 dsh 的现状形态，本工程沿用（§5.3）。
- **假设（⬜ 待验证 P0-6/O7）**：macOS 模板图规范（尺寸、命名 `*Template.png`、深浅色对比度）与 Windows 高 DPI 呈现效果需实机截图确认（§11.2 O7）。
- **约束**：不做全局快捷键、开机自启、托盘常驻长任务（§5.8；O8 属 Phase 2）。
- **约束**：v1 关窗即退出，托盘**不是**「隐藏窗口」的落点。
- **约束**：Linux 托盘依赖桌面环境对 StatusNotifier/AppIndicator 的支持（⬜ 三平台实测记录，§9.3）；不支持时按 FR-003-005 降级。
